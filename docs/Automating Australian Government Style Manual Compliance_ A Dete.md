# An Implementation-Ready Technical Plan for Automated Australian Government Style Manual Compliance

## TL;DR
- **Build a deterministic-first, tiered "detector-proposes / model-verifies" linter — not an LLM that "reads the whole manual."** Run all cheap rules on every span; reserve embeddings and LLMs only to *suppress false positives* and handle the ~25% of rules that need judgement. This is the architecture LanguageTool, Vale, and Grammarly converged on, and the evidence says it is the only one that keeps user trust.
- **Adopt Vale's proven scoping/rule-encoding model for the mechanical tier and keep the custom FastAPI engine for orchestration, semantic tiers, and middleware; drop the Tiptap/ProseMirror document runtime** — it is over-engineered for the three stated deployment modes, where markdown segmentation is sufficient.
- **The prior "inverted-index refactor" is directionally right but its acceptance gates are miscalibrated.** For a compliance linter, precision (not 90% recall) is the metric that determines adoption. The Style Manual is published on GovCMS/Drupal (maintained by the APSC) with a highly regular page template and a dated quarterly Changelog, and is almost certainly CC BY 4.0 (the Commonwealth default) — which makes automated ingestion and change-detection tractable.

## Key Findings

1. **Every mature system in this space is deterministic-first with ML as a false-positive filter, not a rule engine.** Vale parses documents into an AST, scopes rules to prose elements (heading/text/sentence), and runs entirely offline; LanguageTool combines XML pattern rules, Java rules and n-gram confusion rules, and its own docs state the rule of thumb that "precision should be at least 0.995 for very common words and 0.99 for other words … a high precision should be preferred," with a published factor table (p=0.999, r=0.979) showing recall deliberately traded away for precision, and a `RegexAntiPatternFilter` to kill false alarms. Grammarly's GECToR tags edits ("keep/delete/append/replace") rather than rewriting, achieving F0.5 of 72.4 (single-model XLNet) / 73.6 (ensemble) on BEA-2019 at up to 10× the speed of a Transformer seq2seq system. The consistent lesson: **false-positive noise, not missed errors, is what destroys trust in a writing linter.**

2. **LLMs cannot reliably follow or check ~800 simultaneous constraints in one context.** IFEval-family benchmarks (IFEval, FollowBench, ComplexBench) show frontier models degrade sharply as the number of simultaneous constraints rises; instruction-following collapses well before hundreds of rules. This kills the naive "inject the whole manual into the system prompt" design and mandates **per-span rule retrieval** so the model only ever adjudicates a handful of candidate rules at once.

3. **LLM-as-judge is usable only when decomposed into atomic, binary, single-rule checks.** The literature is unanimous: holistic scoring is unreliable (position bias, verbosity bias, self-preference, kappa deflation of 30–40 points between raw agreement and chance-corrected agreement), but **per-criterion binary verdicts reach the highest reliability** (one framework reports ~87% exact accuracy, κ≈0.642 for binary criteria vs. much lower for ordinal). [arXiv](https://arxiv.org/html/2603.00077v2) This exactly matches a "one rule, one yes/no + span + reason" adjudication contract.

4. **Australian government hosting is the binding constraint, and it is subtler than "is Claude in Sydney?"** AWS Bedrock is IRAP-assessed at PROTECTED — the 2025 H1 report (assessment completed by an ASD-certified assessor in September 2025) brought the total to 168 services at PROTECTED, and Bedrock was first added at PROTECTED in the 2024 H1 assessment — and Claude models are available in the Sydney region. But Bedrock's default inference-profile routing (`apac.*`, `global.*`) can process a Sydney-originated prompt in Tokyo, Seoul, Mumbai or Singapore. [Sjramblings](https://sjramblings.io/keeping-ai-workloads-sovereign-on-aws/) Only **in-region on-demand** or the **Australian `au.*` Geo profile** keeps data in Australia, and IRAP is an *assessment input to each agency's own risk decision*, not a certificate that covers your workload. [Cybernion](https://cybernion.com.au/insights/irap-for-aws/) This forces a **small-model / on-prem fallback** for anything above OFFICIAL:Sensitive.

5. **The Style Manual is a favourable ingestion target.** It runs on **GovCMS (Drupal)** — confirmed by the site's own accessibility statement ("The Style Manual uses GovCMS, which is built using Drupal core") — and is maintained by the **Australian Public Service Commission (APSC)**. It uses a highly regular page template: "Guidance" headings *are* concise rule statements, examples are labelled "Write this / Not this," and each page carries "Release notes," an "Evidence"/references block, and a "This page was updated [date]" timestamp. Changes are published in a dated, page- and heading-level-granular **quarterly Changelog**. There is **no public API or structured export** — extraction is HTML-scraping — but the regularity makes LLM extraction reliable and the Changelog is a ready-made change-detection signal. Licensing is almost certainly **CC BY 4.0** (the Commonwealth default across agencies), but this must be verified on the Style Manual's own copyright page before relying on it — the manual's *citation style* file is separately published under CC BY-SA 3.0, so do not assume.

## Details

### 1. Problem decomposition: a defensible taxonomy of Style Manual rules

Analysing the manual's six sections (Grammar/punctuation/conventions; Structuring content; Referencing and attribution; Accessible and inclusive content; Writing and designing findable content; Content types) against the ~801 extracted rules, I propose five classes. Proportions are my estimates calibrated to the manual's content weighting and comparable style-guide rule packages (Vale's Microsoft/Google packages, GDS's `gds-vale-styles`):

| Class | Est. share | Example rules | Checking machinery |
|---|---|---|---|
| **A. Mechanical / deterministic** | ~30% | one space after full stop; no full stop after contractions like "Dr"; en dash in number ranges; "per cent" vs "%"; time formats | Regex + structural checks over segmented markdown. Vale-style `existence`/`substitution`. Near-zero cost, near-100% precision achievable. |
| **B. Lexical-with-exceptions** | ~25% | spell out numbers under 10 (many exceptions); preferred/deprecated terms; inclusive-language substitutions; Commonwealth entity names; ministerial titles | Lexicon lookup + exemption masks (URLs, code, quotes) + light POS/context. Precision requires the exception handling — this is where naive linters generate noise. |
| **C. Structural / formatting** | ~15% | sentence-case headings; bullet lists parallel and not ending in full stops; table caption rules; link-text rules | Markdown segmentation + ancestry (ZONE_*/ANCESTOR_* features). Deterministic once structure is parsed. |
| **D. Contextual-semantic** | ~20% | plain-language / readability; passive voice where active is clearer; over-long sentences; "write for your reader"; acronym defined on first use | spaCy annotations + small language model (SLM); embedding similarity to exemplars; cross-span REL_* relations. Detector proposes, model verifies. |
| **E. Judgement / intent** | ~10% | is this the right content type? is the tone appropriate for the audience? is this culturally appropriate re Aboriginal and Torres Strait Islander peoples? | **Should NOT be automated.** Handle via education, checklists, and human-review prompts surfaced in-product — never as auto-flags. |

**The single most important design consequence:** roughly 55% of rules (A + C) are cheaply and precisely automatable; ~25% (B) are automatable only with disciplined exemption handling; ~20% (D) need ML verification; ~10% (E) must be handled by *prompting the human*, not by flagging. A system that treats all classes identically — the failure mode the user describes — is guaranteed to drown class-A signal in class-D/E noise. **Class E rules should appear in the UI as a pre-submit checklist ("Have you confirmed the content type suits the user need?") and in training material, not as inline squiggles.**

### 2. Recommended target architecture

**Data flow:** `Input (text/markdown/Word/LLM-output) → Preprocessing (markdown segmentation, ancestry, exemption spans, sentence cache, spaCy annotations) → Feature extractor (boolean feature vector per span) → Indexed dispatcher (candidate rule set per span) → Tier 1 deterministic (all cheap rules, always) → Tier 2 lexical/pattern + exemption masks → Tier 3 SLM/embedding verification (only for candidate semantic rules) → Tier 4 LLM adjudication (batched, only for low-confidence Tier-3 or judgement-adjacent) → Findings with provenance, severity, mutation_class → Surface (batch report / middleware annotations / editor)`.

**Adjudicating the three key design questions the brief demands:**

**(a) Inverted index vs embedding retrieval vs "just run all cheap rules."** The right answer is a **hybrid that the prior refactor plan half-states**: *run all Tier-1/Tier-2 deterministic rules unconditionally* (they are individually sub-millisecond; gating them adds complexity for no gain and risks recall loss), and *use the feature-based inverted index purely to decide which expensive Tier-3/Tier-4 rules to invoke.* A **feature-based inverted index beats embedding retrieval** for this problem because Style Manual rules fire on discrete, observable features (there is a currency symbol; this is a heading; a passive construction was detected), not on fuzzy semantic similarity — feature/metadata filtering is more precise, is debuggable, and costs nothing at inference. Embedding retrieval earns its place in only one spot: matching a flagged span against *exemplar sentences* to suppress Tier-1 false positives (Tier 3). So: **deterministic rules always-on; inverted index gates the model tiers; embeddings do exemplar similarity — not rule routing.** This corrects the refactor plan's implication that all ~801 rules (including trivial regexes) should be index-gated.

**(b) Rich document runtime (Tiptap/ProseMirror) vs markdown segmentation.** For the three stated modes — batch processing, LLM middleware, and a web editor — a **full canonical AST document runtime with UUIDv7 node IDs and lossy Word round-tripping is over-engineering.** Markdown segmentation with stable content-hash keys delivers the ZONE_*/ANCESTOR_* structure that class-A/C rules need, at a fraction of the complexity. The Octavius "document runtime" solves a problem (rich collaborative editing with perfect Word fidelity) that none of the three modes actually requires; its own spec concedes Word conversion is lossy. **Recommendation: markdown as the canonical interchange format; use Tiptap only as a thin *front-end* editor that serializes to markdown, and treat Word ingestion as one-way import (pandoc) rather than round-trip.** Reserve the AST-runtime investment for a later phase only if real collaborative-authoring demand emerges.

**(c) Build vs adopt.** Neither pure "extend Vale" nor "keep rebuilding everything." **Adopt Vale's battle-tested scoping model and YAML rule conventions for Tiers 1–2, and keep the custom FastAPI engine as the orchestrator for the tiered pipeline, the semantic tiers, and the three deployment surfaces.** Reasoning: Vale already solves markup-aware scoping, offline execution, and declarative `existence`/`substitution`/`occurrence` rules extremely well, and GDS has publicly demonstrated a *government* style guide encoded as Vale styles (`alphagov/gds-vale-styles`) — so the mechanical tier is a solved problem you should not rebuild. But Vale cannot do cross-span REL_* relations, SLM verification, LLM adjudication, the middleware pattern, or per-instance/telemetry-driven confidence promotion — which is exactly what makes this project novel. Rebuilding Vale's deterministic core in Python would waste effort; rebuilding the semantic/middleware layer inside Vale's Go plugin model would fight the tool. The clean seam is: **Vale (or a Vale-compatible Python re-implementation of just the scope+existence primitives) for A/C rules; custom engine for B-exemptions, D-semantics, E-prompts, and all orchestration.** If cross-process calls to the Go binary are undesirable on Render/on-prem, port only Vale's *scoping semantics and rule schema* (not the whole tool) into the Python engine — but do adopt the schema, because it is proven and community-legible.

**Where the priors got it right:** Octavius's deterministic-first / fail-visible-never-silent / provenance-everywhere principles are correct and should be preserved verbatim; its tiered pipeline (deterministic → pattern → SLM → LLM) is the right shape; caching keyed on `(rule_id@version, node_id, content_hash)` is exactly right. The refactor plan's frozen boolean feature vocabulary, exemption masks in a rule's `none_of` slot, `mutation_class` (safe_replace / requires_rewrite / human_review), and per-document firing budget are all excellent and should survive into the target design.

### 3. Rule representation

Adopt a single rule contract (YAML front-matter + typed validator), converging the two priors:

```yaml
id: numbers.spell-under-ten
version: 3
source_url: https://www.stylemanual.gov.au/grammar-punctuation-and-conventions/numbers-and-measurements/choosing-numerals-or-words
source_quote: "Use words for numbers under 10 (zero to nine)."
class: lexical_with_exceptions
tier: 2
selector:                 # Vale-style scope + feature predicate
  scope: [text]
  all_of: [HAS_CARDINAL_UNDER_10]
  none_of: [ZONE_TABLE_CELL, EXEMPT_URL, EXEMPT_CODE, EXEMPT_QUOTE, HAS_ADJACENT_UNIT]
validator:
  kind: function           # regex | ast_pattern | lexicon | function | embedding | slm_prompt | llm_prompt
  ref: numerals.spell_small_cardinals
mutation_class: safe_replace
severity: warning
tests:
  positive: ["There were 3 submissions."]
  negative: ["Section 3 of the Act", "Page 7", "3 mm clearance"]
  edge:     ["3 to 9 people", "the 1990s"]
lifecycle: active          # draft | candidate | active | deprecated
confidence: 0.94           # telemetry-driven, promotes tier downward over time
```

**Mandatory example-based testing** (positive/negative/edge) is non-negotiable — it is how LanguageTool controls precision and how Vale validates rules, and it is the artefact that makes automated ingestion safe. **Overlap/duplication:** cluster rule-statement embeddings and merge near-duplicates at ingestion (as Octavius proposes). **Conflict/precedence:** run each new rule's positive examples against the existing active rule set; any rule that fires on another's *correct* example is a conflict flagged for human resolution. Stacked organisational rulebooks resolve by explicit precedence order (agency overrides > Style Manual default), with the winning rule's provenance always shown. **Provenance is mandatory on every finding** — `source_url` + verbatim `source_quote` — both because a CC BY licence requires attribution and because "the manual says X, here" is what converts a flag into a trusted, actionable edit.

### 4. Rule ingestion and maintenance

**Pipeline:** headless scrape of GovCMS HTML (probe `/sitemap.xml` first — very likely present on Drupal) → HTML→markdown → chunk by heading (the template makes each "Guidance" H2/H3 a rule candidate) → LLM batch extraction of `{statement, examples, class, suggested validator}` via the Anthropic Batch API → auto-generate positive/negative/edge cases from the page's "Write this / Not this" blocks → generate executable validator with a bounded retry loop that tests against the examples → **human review gate** → near-duplicate clustering → conflict detection. This is essentially Octavius's ingestion pipeline, and it is sound; the Style Manual's confirmed template regularity makes it reliable.

**Change detection:** poll the quarterly **Changelog** page and each page's "This page was updated [date]" timestamp; diff content hashes. The Changelog is dated and heading-level granular (e.g. "Centuries – Write all centuries with numerals (3rd century). Under the previous rule, both … were acceptable"), so it maps almost directly onto rule-version bumps. Run this as a scheduled GitHub Action quarterly plus an ad-hoc trigger.

**Human-in-the-loop economics for ~801 rules.** Full first-pass review of ~801 auto-extracted rules at a realistic 3–5 minutes each is on the order of 40–65 person-hours — a few focused days for one editor, not a research program. But **do not review uniformly.** Prioritise: (1) all `safe_replace` rules that will auto-fix (highest blast radius if wrong) — review first and hardest; (2) rules with the highest projected fire-rate on the calibration corpus; (3) rules where auto-generated tests failed or were sparse. Defer low-fire, low-severity `human_review`-class rules to a rolling backlog. Thereafter, quarterly maintenance is bounded by the Changelog delta (historically a few dozen page-level changes per release).

### 5. The three deployment modes, concretely

**(a) Batch document processing.** A stateless FastAPI job (or CLI) that segments each document, runs Tiers 1–2 synchronously, and queues Tier-3/4 candidates into a single **Anthropic Batch API** job (50% discount, 24-hour SLA). [CloudZero](https://www.cloudzero.com/blog/claude-api-pricing/) Group findings per rule, apply the per-document firing budget, emit a report with provenance and severity. This is the cheapest mode and the natural home for the frontier-LLM tier.

**(b) LLM middleware — one recommended pattern.** Use **post-hoc validate-then-annotate, with at most one bounded regeneration, and never silent rewriting.** Concretely: the user's LLM produces a response; the response is validated against the active writing profile using Tiers 1–3 (deterministic + SLM, no per-keystroke LLM); findings are shown *alongside* the response as annotations. Offer the user (or the calling system) exactly **one** optional regeneration in which the findings are injected as explicit constraints. Reject the alternatives on evidence: injecting the whole guide into the system prompt fails because models can't honour hundreds of constraints (IFEval); unbounded validate-and-regenerate loops cause "needless regeneration land" — with 5 guards at 90% accuracy you get a false-positive block ~40% of the time, and practitioners report each retry adding 1.5–3s with observed *retry divergence* (outputs getting worse and over-cautious). Constrained decoding is impractical for prose-level style. **Cost/latency bound:** Tiers 1–3 add ~150–250ms (Haiku-class or local SLM); [Kalvium Labs](https://www.kalviumlabs.ai/blog/guardrails-for-llm-applications/) the single optional regen is opt-in, so p50 latency stays low and the model is never silently overruled — satisfying the "fail visible, never silent" principle.

**(c) Interactive web editor.** Three-lane latency architecture: **Lane 1 (keystroke, <100ms):** Tier-1/2 deterministic rules in-process over the changed span only (incremental revalidation keyed on content hash), rendered as inline squiggles. Grammarly's own experience — a target that "the entire GEC model must run at 100+ tokens/second" and an on-device T5 optimisation from 70 to 297 tokens/second — shows keystroke-latency prose checking is a solved engineering problem when you keep the model small and local. **Lane 2 (debounced ~500ms–1s, on pause):** Tier-3 SLM/embedding semantic checks over the current paragraph, async, non-blocking. **Lane 3 (on-demand / pre-submit):** Tier-4 LLM adjudication and class-E checklist. **Trust-preserving UX (the decisive factor):** every finding carries the Style Manual quote + link; per-instance "ignore" and "ignore forever"; "accept fix" for `safe_replace`; "suggest rewrite" (never auto-apply) for `requires_rewrite`; "acknowledge" for `human_review`; profile scoping (formal correspondence / standard / social) so only relevant rules fire. Accept/dismiss events feed telemetry.

### 6. Evaluation and trust

**Gold corpus.** Build two labelled sets per the refactor plan — `should_fire/` and `should_not_fire/` — but expand to a **stratified gold corpus** with per-rule annotations across genres (ministerial correspondence, web content, forms, social) and measure **inter-annotator agreement**, because style judgements (class D/E) have genuinely low IAA and you must not set targets above human agreement.

**Are the refactor plan's gates (≥70% noise reduction, ≥90% recall, p50<200ms/p95<700ms) the right numbers?** Partly. **The latency gates are excellent** and align with production guardrail experience — keep them. **The ≥70% reduction in findings on `should_not_fire` is the right *kind* of gate** (it directly targets the noise that destroys trust). **But ≥90% recall as a global gate is wrong for a compliance linter** and contradicts the precision-first philosophy that LanguageTool, Vale and Grammarly all adopt. LanguageTool's own documentation targets precision ≥ 0.995/0.99 while *accepting* recall down toward 0.98–0.90, because a false alarm is far more costly to trust than a miss. **Recommendation: replace the single global recall gate with per-rule, per-class gates:**
- Class A/C (mechanical/structural): **precision ≥ 0.98, recall ≥ 0.95** (these should be near-perfect).
- Class B (lexical-with-exceptions): **precision ≥ 0.95** (recall secondary; exemptions matter more than coverage).
- Class D (semantic): **precision ≥ 0.85**, surfaced as *suggestions* not errors; use a **selective-prediction confidence threshold** so low-confidence detections are withheld rather than shown.
- Overall: **≥70% finding reduction on `should_not_fire` vs. the legacy "run everything" baseline** (keep), plus **accept-rate ≥ 60%** as the north-star trust metric (a rule whose suggestions are dismissed >40% of the time is auto-demoted).

**Telemetry-driven tuning.** JSONL events (fire, accept, dismiss, ignore-instance, ignore-forever) aggregate into per-rule precision estimates bucketed by `mutation_class`. Rules promote toward cheaper tiers as confidence rises and auto-demote/quarantine when dismiss rates spike — this is the mechanism that keeps noise down over time and is the single most important operational loop.

**False-positive management strategy (explicit):** (1) exemption masks (URL/code/quote) in every rule's `none_of`; (2) Tier-2 pattern + Tier-3 embedding-to-exemplar suppression before any flag surfaces (the neuro-symbolic "detector proposes, model verifies" pattern shown to cut false positives in analogous static-analysis settings, where LLM verification of detector output removed infeasible-path false positives); (3) per-document firing budget; (4) selective prediction on semantic tiers; (5) telemetry auto-demotion. **Binary, single-rule LLM adjudication** (not holistic scoring) because the judge literature shows binary per-criterion verdicts are the only reliable mode.

### 7. Cost model

Assume an APS deployment processing **50,000 documents/month** at ~500 words each, plus interactive editing.

- **Tier 1–2 (deterministic + lexical):** run on 100% of spans, **~$0 marginal cost** (CPU only; fits the Render free tier / on-prem container). This is why deterministic-first is not just a quality choice but an economic one.
- **Tier 3 (SLM + embeddings):** local `bge-base-en-v1.5` embeddings + a small local model or Haiku-class calls on candidate semantic spans only. If ~30% of docs trigger a semantic candidate needing a hosted call at ~1.5k input / 300 output tokens, at **Claude Haiku 4.5 ($1/$5 per MTok)** via **Batch API (50% off → $0.50/$2.50)**: ≈ 15,000 docs × (1.5k×$0.50 + 0.3k×$2.50)/1e6 ≈ **~$22/month**.
- **Tier 4 (frontier LLM adjudication):** reserved for low-confidence/judgement-adjacent findings, say 10% of docs, batched on **Claude Sonnet ($3/$15, or $1.50/$7.50 batched)** at ~2k in / 500 out: 5,000 × (2k×$1.50 + 0.5k×$7.50)/1e6 ≈ **~$34/month**.
- **Prompt caching** (cache reads at ~10% of base input, i.e. up to 90% off) on the shared rule/exemplar context drives Tier-3/4 input cost down further.

**Total variable model cost ≈ $50–70/month at 50k docs** — trivial. **The economics force three design choices:** (1) do as much as possible deterministically, because it is free and fast; (2) use the Batch API for all non-interactive model calls (halves cost); (3) keep the interactive editor's per-keystroke path model-free (local SLM only) — a per-keystroke frontier-LLM call would be both too slow and, at scale, orders of magnitude more expensive than the entire batch pipeline.

### 8. Australian government deployment constraints (feeds the roadmap)

- **The AI-in-government policy applies and has hard dates.** The DTA's *Policy for the responsible use of AI in government* v2.0 came into effect **15 December 2025** and mandates an **AI impact assessment for each in-scope use case**; its first new mandatory requirement begins **15 June 2026**, with remaining requirements from December 2026. The updated *AI Impact Assessment Tool*, an *AI technical standard*, and *Guidance on AI procurement* (published under the *AI Plan for the APS 2025*) [Digital Transformation Agency](https://www.dta.gov.au/media-releases/ai-policy-overhauled-new-impact-assessment-tool-and-procurement-guidance) will govern any deployment. Budget for an impact assessment as a project deliverable, not an afterthought.
- **Data residency dictates the model tier.** For OFFICIAL content, hosted Claude via **Bedrock Sydney in-region on-demand** or the **`au.*` Geo profile** is defensible (keeps data in Australia; Bedrock is IRAP-assessed to PROTECTED). **Never use `apac.*`/`global.*` inference profiles for government text** — they can process prompts offshore. [Sjramblings](https://sjramblings.io/keeping-ai-workloads-sovereign-on-aws/) For OFFICIAL:Sensitive/PROTECTED where text cannot leave the boundary, **fall back to on-prem/local small models** (the deterministic + local-SLM tiers already run with no external calls; only Tier-4 adjudication is degraded, which is acceptable because it is the smallest slice). IRAP is an input to the agency's own authorisation — the workload still needs its own assessment. [Cybernion](https://cybernion.com.au/insights/irap-for-aws/)

### 9. Phased delivery roadmap (solo lead + Claude Code, GitHub Actions, FastAPI, React/Vite, spaCy, local bge-base embeddings, SQLite/parquet, Render, Batch API)

- **Phase 0 — Rule-contract + gold corpus (2–3 wks).** Freeze the unified rule schema (§3). Build the stratified gold corpus with `should_fire`/`should_not_fire` and per-rule labels. **Go/no-go:** ≥150 labelled docs with measured IAA.
- **Phase 1 — Ingestion + Tier 1/2 on the inverted index (3–4 wks).** Scrape GovCMS, LLM-extract via Batch API, auto-generate tests, human-review the top-priority `safe_replace` and high-fire rules. Ship deterministic + lexical tiers with exemption masks. **Go/no-go:** class-A/C precision ≥0.98 on gold; ≥70% finding reduction on `should_not_fire` vs legacy.
- **Phase 2 — Semantic tier + false-positive suppression (3–4 wks).** spaCy annotations, local bge embeddings, exemplar suppression, selective prediction. **Go/no-go:** class-D precision ≥0.85 with withheld low-confidence; overall accept-rate ≥60% in dogfooding.
- **Phase 3 — Interactive editor with three-lane latency (3–4 wks).** Tiptap→markdown front end, incremental revalidation, trust UX (ignore/ignore-forever/accept/suggest), telemetry. **Go/no-go:** keystroke p50<100ms, semantic lane p95<700ms.
- **Phase 4 — LLM middleware (2–3 wks).** Validate-then-annotate with one bounded regen; MCP server interface. **Go/no-go:** no silent rewrites; regen opt-in; p50 added latency <250ms.
- **Phase 5 — Government hardening (ongoing).** On-prem container with no external calls except configured model endpoint; Bedrock `au.*`/in-region wiring; DTA AI impact assessment; telemetry dashboard for rulebook maintainers. **Go/no-go:** passes agency IRAP/authorisation and impact assessment.

Env-flag cutover (`legacy | indexed`) with documented rollback throughout, exactly as the refactor plan specifies.

## Recommendations
1. **Commit to deterministic-first now.** Ship Tiers 1–2 (mechanical + lexical-with-exemptions) covering ~55% of rules at ≥0.98 precision before touching any semantic ML. This alone solves most of the user's problem and builds trust. *Threshold to proceed to ML:* class-A/C precision ≥0.98 and ≥70% noise reduction on `should_not_fire`.
2. **Replace the global 90% recall gate with per-class precision gates** (§6). Track **accept-rate ≥60%** as the primary trust metric; auto-demote any rule dismissed >40% of the time.
3. **Adopt Vale's rule schema/scoping; drop the Tiptap document runtime; keep markdown canonical.** Reserve the AST runtime for a future phase only if collaborative authoring is demanded.
4. **Middleware = validate-then-annotate + one bounded regen, never silent rewrite.** This is the only pattern the evidence supports for production.
5. **For government hosting, default to local/on-prem for the deterministic+SLM tiers and use Bedrock `au.*`/in-region only for Tier-4.** Never route government text through `apac.*`/`global.*` profiles. Complete a DTA AI impact assessment as a Phase-5 gate (note the 15 June 2026 first mandatory requirement).
6. **Do not automate class-E judgement rules.** Surface them as pre-submit checklists and training, not inline flags — mis-flagging judgement calls is the fastest way to lose editor trust (the DTA's own research found personal-preference "capital letter" arguments are the core pain point; [Digital Transformation Agency](https://www.dta.gov.au/blogs/reimagining-style-manual) a tool that adds *machine* opinions to that fight will be rejected).

## Caveats
- **Rule counts and class proportions are estimates.** The exact total of guidance pages could not be confirmed (no accessible full index; ~100–150 topic pages estimated), and the ~801 figure is the user's prior extraction. Re-derive class proportions empirically once the rulebook is re-ingested.
- **The Style Manual's licence must be verified before reuse.** CC BY 4.0 is the Commonwealth default and almost certainly applies, but this was not confirmed on the manual's own copyright page (its citation-style file is separately CC BY-SA 3.0). Confirm before scraping and redistributing rule text.
- **Model pricing and availability change fast.** Anthropic's tiers (Haiku 4.5 $1/$5; Sonnet $3/$15 with Sonnet 5 intro pricing; Opus 4.8 $5/$25; [AI Pricing Guru](https://www.aipricing.guru/anthropic-pricing/) Batch API 50% off; caching ~90% off cached input) and Bedrock's Sydney model matrix and inference-profile routing were current at time of writing but must be re-verified at procurement; treat the cost model as an order-of-magnitude guide.
- **IRAP status must be verified per engagement.** "168 services at PROTECTED (2025 H1), Bedrock included" is a snapshot; the agency's own authorisation and the current AWS Artifact package are authoritative. [Cybernion](https://cybernion.com.au/insights/irap-for-aws/)
- **Style judgement has irreducibly low inter-annotator agreement.** Class-D/E targets must be capped at measured human agreement; some rules will never be safely automatable, and the system's credibility depends on admitting that in-product.
- **LLM-as-judge reliability is conditional.** It holds only for atomic, binary, single-rule adjudication with provenance; do not let scope creep turn Tier 4 into a holistic "score this document" judge, which the literature shows is unreliable.
