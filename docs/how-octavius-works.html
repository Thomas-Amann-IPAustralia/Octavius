How Octavius Works

From building the rulebook to marking up your writing.

Octavius is a proofreading assistant for Australian Public Service content. It turns the Australian Government Style Manual into hundreds of precise, tested checks — then runs them across your document and underlines what needs attention, with a reason and a fix for each one.

Job one

Building the rulebook

Reading the whole Style Manual and turning each piece of advice into a check a computer can run — carefully, and once.

Happens occasionally, behind the scenes

Job two

Applying the rulebook

Taking your document, running the finished checks against it, and showing you the results — live.

Happens the instant you stop typing

Job one · Building the rulebook

An assembly line that turns guidance into tested checks

The Style Manual is a large website written for people. A six-step pipeline reads it and refines it, one stage at a time, into a sealed rulebook the app can load. Every rule traces back to a real page.

1
Style Manual site → local copy

Copy the pages

Save a tidy local snapshot of every Style Manual page, so the work runs against something stable. When the site refuses an automated visit, Octavius loads the page in a real browser, just like a person would.

2
a page → individual rules

Extract the rules

Read each page and pull out its distinct pieces of advice as separate, self-contained rules — each with a plain summary, the reason behind it, and a link back to its source page.

3
a rule → a runnable check

Write the check

Turn each plain rule into a precise test. How it's checked depends on the kind of issue:

pattern — spot a run of characters word-list — scan for listed terms structure — check the shape human judgement — flag, don't automate
3.5
a rule → when it applies

Describe when to check

Tag each rule with the kinds of text it cares about — and the kinds it must ignore (like web addresses or code). Also record how fixable it is: safe to auto-fix, needs a rewrite, or needs a human.

4
every rule → pass or fail

Test every rule

Each rule sits an exam against practice sentences: some it should catch, some it must leave alone. A rule passes only if it gets every one right.

The quality gate — only rules that pass their exam are ever allowed into the finished rulebook.
5
a failed rule → a second attempt

Fix the failures

Any rule that failed gets rewritten and re-tested. Every correction is logged, so there's always a record of what changed and why.

6
passing rules → the sealed rulebook

Publish

Pack all the passing rules into one compact, sealed file — the finished rulebook, and the only rule file the running app ever loads.

Job two · Applying the rulebook

What happens the moment you stop typing

Everything below runs in a fraction of a second, each time you pause. The clever part is the middle: Octavius describes your text first, then runs only the handful of rules that could possibly apply.

Step 1

✍️ Your document

You type in a rich editor that knows its own structure. Octavius waits about 0.4s after you stop before checking.

Step 2

🧩 Split into zones

Break the document into natural pieces — headings, paragraphs, bullets, table cells. Code is set aside, untouched.

Step 3

🩹 Mask what to ignore

Cover up web addresses, code, quotes and names so they're never proofread as if they were ordinary prose.

Step 4

🔖 Take a fingerprint

Jot down what each piece is like: a heading? contains a date? written in passive voice? — just facts, no judgement yet.

Step 5

🗂️ Shortlist the rules

Use the fingerprint to look up only the rules that could apply to text like this — skipping the rest instantly.

Step 6

🔎 Run the checks

Run the shortlisted rules and note every spot they apply. Results for unchanged text are remembered, not redone.

Step 7

🧹 Tidy the results

Cap repeats, drop duplicates, merge overlaps, and hush whole-document rules on drafts that are too short to judge.

Step 8

🖍️ Show you

Underline the exact words in place, and list every finding with its reason, a Style Manual link, and a fix.
